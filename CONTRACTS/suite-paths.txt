# SUITE PATH DECLARATIONS (CI-2, harbor#150) — which changes select which suite.
# bin/suite-select.sh is the decision procedure; the reasoning lives here.
#
#   <suite>      <glob> [<glob> ...]     runs when a changed path matches a glob
#   <suite>      always                  runs unconditionally
#   @no-suite    <glob> [<glob> ...]     paths that legitimately select nothing
#
# Blank lines and `#` lines are ignored. Globs are `case` patterns where `*` crosses `/`, so
# `bin/*` is everything under bin/ at any depth. `@no-suite` CLASSIFIES a path; it never
# suppresses a selection — a suite that declares a path still runs for it.
#
# THE RULES THAT KEEP THIS SAFE. The failure to prevent is a floor change quietly taking the
# cheap lane, and it is silent: the run comes back green and shorter.
#   1. Over-selection is the safe direction. Nearly every suite declares `bin/*`; narrowing
#      within bin/ needs per-suite evidence. Two suites (deny-hash-test, usage-aggregate-test)
#      name no repo path in their source and build their subjects at runtime, which is the
#      whole argument for declaring generously.
#   2. An unclassified path selects every suite. A new top-level path is expensive by default.
#   3. The selector does not judge its own change: touching this file, CONTRACTS/suites.txt,
#      the selector, its suite, the linter, the runner or a workflow runs everything. The one
#      exception is rows APPENDED here or to CONTRACTS/suites.txt with keys the base did not
#      have — see APPENDABLE in bin/suite-select.sh; any removed or edited line is rule 3 again.
