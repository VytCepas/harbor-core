# `harbor` — the L0 command surface (CLI-1, harbor#42)

`CONTRACTS/orchestrator-json.md` freezes the Fleet CLI's seam and **nothing froze
Helm's**. Four documents described Helm as *"the environment + the `harbor`
command"* while no ticket defined a single subcommand: a noun with no verbs. This
file is the verb list, the exit-code contract, and the `--json` rule.

## What `harbor` is not

**Not a launcher.** `claude` stays the command you type. Helm's logic is ambient —
hooks in `settings.json`, `~/.claude/CLAUDE.md`, the installed skills — and it
applies to every session however it starts. A wrapper terminal would protect only
the sessions someone remembered to start through it, which is exactly when a
security floor is least useful. Checked upstream rather than assumed: upstream ships
no launcher command (`install/package.json` has no `bin` field).

`harbor` is a **management** command — install, verify, repair, report. Closer to
`brew` than to `tmux`.

## Verbs

Every row dispatches to a script that already exists. This table is the contract:
lint rule **CLI1** fails if a verb's script is missing, if `bin/harbor`'s own verb
list disagrees with this table, or if a `bin/*.sh` appears in neither this table
nor the internal list below.

### Why `--help` is not generated from this file at runtime

The obvious reading of harbor#42's "generated from the contract, not hand-written"
is that `bin/harbor` should parse this table when asked for help. It must not:
`harbor restore` exists for the case where the machine is broken, and a recovery
command that reads a markdown file out of a repo checkout fails exactly when it is
needed — the same argument that makes this POSIX sh rather than Bun.

So the verb list is embedded in the dispatcher, and **lint rule CLI1 asserts the
two are identical**. That satisfies what the requirement is *for* — no
independently-maintained second copy that drifts silently — without making the
recovery path depend on a document. The mechanism is the equality check, not the
generation step.

## Exit codes

Uniform across verbs, because a caller that has to remember per-verb codes will
not:

| Code | Meaning |
|---|---|
| 0 | success |
| 1 | the verb ran and reported a problem (lint violation, stale STATUS, broken citation, failed probe) |
| 2 | usage error — unknown verb, unknown flag, missing argument |
| 3 | the verb could not judge (D-29 unchecked, D-49): a missing binary or verifier, a registry or store it cannot read. Nothing was looked at, so it is never a green. The dispatcher forwards it verbatim; `harbor` itself never exits 3 |
| 127 | the verb's script is not installed next to the dispatcher |

**Nonzero is never swallowed.** The dispatcher `exec`s (or runs and forwards) the
target's exit status verbatim; it never remaps 1 to 0 to look calmer. A wrapper
that hides its child's failure is the fail-open shape this repo keeps finding.

## `--json`

`--json` is passed through untouched to verbs whose row says yes. Verbs without it
must not silently accept and ignore the flag — that is worse than refusing, because
a caller parsing empty output cannot tell "no data" from "flag not supported". The
dispatcher exits 2 with a message naming the verbs that do support it.

## `harbor status obligations --json`

The one shape the console's Obligations tab reads (harbor#1053, frozen by the night-stack contract of 2026-10-06). It is read, never
written: `status-obligations.sh show` takes no lock and reads `current.json` and `sources.json` from `$HARBOR_OBLIGATION_DIR`.

```json
{
  "generated_ts": "2026-10-06T01:30:00Z",
  "sources": { "<source>": { "ok": true, "reason": "", "ts": "2026-10-06T01:25:00Z" } },
  "obligations": [
    { "id": "pr:owner/harbor#1072", "kind": "pr", "subject": "owner/harbor#1072", "repo": "harbor",
      "owner": "session:<id>|agent:<id>|check:<id>|operator", "title": "short title, never command text", "link": "an https URL or \"\"",
      "opened_ts": "2026-10-03T09:00:00Z", "deadline_ts": "2026-10-06T09:00:00Z or \"\"",
      "state": "open|overdue|closed|abandoned", "closed_by": "<event id>|reconcile|operator|\"\"", "closed_ts": "… or \"\"", "age_s": 3600 }
  ],
  "proposals": [],
  "read_ts": "2026-10-06T01:31:00Z"
}
```

- Every row carries every key above, in that order, with `""` for one the ledger has no value for. `age_s` is seconds from `opened_ts` to
  `read_ts` for every state, counted at read; a closed row's lifetime is `closed_ts` minus `opened_ts`.
- `generated_ts` is when the fold last wrote `current.json`, not the clock of the read: a consumer sees how stale the file is as
  `read_ts` minus `generated_ts`. `read_ts` is the read's own clock and is the last key (added by harbor#1115; the rest are unchanged).
  A row stored `open` whose `deadline_ts` has passed is shown `overdue`, so a stale file cannot show an expired row as healthy.
- `sources` is what each source answered on the last reconcile (`ok: false` carries the `reason`; `ts` is the attempt, not the last
  success). A source that did not answer flipped no row. `{}` until a reconcile has run. A `ledger` key (`ok: false`) appears for the
  run that skipped ledger lines which did not parse, and is gone after the next clean one.
- `obligations` is every live row plus every row closed within the last 15 days (the event bus keeps 14, plus a day for its day files);
  an older closed row is no longer listed, and `ledger.jsonl` still holds its history.
- `proposals` is `[]` until harbor#1052; a consumer treats a missing or empty list as none.
- `--since <N>s|m|h|d` keeps the rows opened, closed, or last moved by a transition within the window. An absent ledger prints the
  empty shape and exits 0; a malformed `--since` exits 2.
- `--print` is for a person, not a parser: the count line, then overdue, new and oldest-open rows, a few of each.

## Where it lives

Source of truth is `bin/harbor`; install is a **copy** to `~/.local/bin/harbor`,
the Phase-0 home rule. `harbor` on `$PATH` is the
done-when; a symlink into a repo checkout would make the recovery command depend
on that checkout still existing.

_Owner: **CLI-1** ([harbor#42](https://github.com/VytCepas/harbor/issues/42)).
Consumers: the operator, and any hook that wants one door instead of eleven._
