# Naming and conventions standard

The grammar every name in the metasystem follows. This file holds the rules that are prose by nature: the
principles, the grammar, the symbols, the edge cases, case, and how the lint enforces them. Everything that is a
set is data in `standards/naming/*.tsv`, which `bin/lint-name.sh` reads. This file states no enumeration the
registry owns: the families, verbs, kinds, aliases, surfaces and rules are rows, and their readable views are
generated by `sh bin/lint-name.sh --gen glossary` and `--gen naming-guide`.

It is the only copy of the rule text (D-39). `CONTRACTS/naming.md` was deleted when this landed. Decisions are
cited as **D-n** (§12), and sections keep the draft's numbers, so a citation such as `§3` resolves through the
table below.

| § | Subject | Lives in |
|---|---|---|
| 1 | Vocabulary: terms, top terms, where aliases are allowed | `terms.tsv`, `aliases.tsv`; `--gen glossary` |
| 2 | Hierarchy and levels (D-57) | terms of class `level`, chained by `broader` in `terms.tsv` |
| 3 | Families and verbs | `terms.tsv` classes `family` and `verb`; `--gen cli-tree`, `--gen labels` |
| 4 | Kinds | `terms.tsv` class `kind`; `kinds.tsv` |

## 0. Principles

1. **A name is a list of vocabulary terms, rendered differently on each surface.** One concept has one canonical
   tuple, such as `(drift, undeployed)`, and the tuple gives every surface its name. Each row below runs as a pass
   fixture in `bin/lint-name.sh --self-test`, so an example the lint rejects fails the build:

   | Surface | Rendering |
   |---|---|
   | `bin` | `bin/drift-undeployed.sh` |
   | `command` | `harbor drift undeployed` (D-13) |
   | `check-id` | `drift.undeployed` |
   | `launchd` | `com.harbor.drift.undeployed` |
   | `env` | `HARBOR_DRIFT_UNDEPLOYED_INTERVAL` |
   | `python-module` | `fleet.drift.undeployed` (D-32) |
   | `test` | `tests/drift/undeployed/install.test.sh` (D-14) |

2. **Three independent axes, never mixed:** the **family** (which function it serves: `terms.tsv` class
   `family`, D-17 and D-63) is the first word on a flat surface and the subpackage in code; the **kind** (what sort
   of artifact it is) is the folder; the **layer** (where it sits in the derivation) is the root it lives under,
   never the name.
3. **Hierarchy lives in the vocabulary, not in long names.** Each family has a broader term, so a short name
   expands to a full path: `lint-name` means control plane › audit › lint.
4. **Technical terms are canonical.** Nautical and legacy words are aliases, allowed only on the surfaces
   `aliases.tsv` lists for them.
5. **Each fact is stated once and derived everywhere else.** The registry is the only copy.
6. **The standard describes itself.** It is written in its own terms, obeys its own grammar and is checked by its
   own lint, and harbor carries a scope marker like every other repo (D-37).
7. **Cost is migration planning, never a veto.**
8. **Ids are permanent.** An id is never renamed or reused. A changed meaning gets a new id, and the old one is
   marked deprecated with a successor (D-19).

## 6. Grammar

```ebnf
name          = [ date "-" | ordinal "-" ] [ family "-" ] object [ "-" verb ] ;
object        = term { "-" term } ;
term          = word { "-" word } ;
word          = lower { lower | digit } ;
date          = YYYY "-" MM "-" DD ;
ordinal       = digit digit digit digit ;              (* decision records only, MADR *)
id            = segment { "." segment } ;
segment       = word { "-" word } ;
reference     = [ system "/" ] register ":" id ;       (* D-20 *)
issue-ref     = repo "#" digits ;
finding-key   = tier "/" id ;
env-var       = REPO "_" FAMILY "_" NAME { "_" NAME } ;   (* D-15 *)
command       = system family [ object ] [ verb ] ;     (* D-13; no verb is the default action *)
leaf          = [ "." ] name { "." extension } ;       (* every extension registered, §6.3 *)
```

**Parsing back to the tuple.** `-` joins both words and terms, so the parse is positional: the first word is a
family when the surface requires one, the last word is a verb when it is in the verb set, and everything between is
the object. Families and verbs are disjoint, which makes the parse deterministic.

### 6.1 Surfaces

The renderer for each surface is a row of `standards/naming/surfaces.tsv`, with an example that runs as a pass
fixture. `sh bin/lint-name.sh --gen naming-guide` renders the table. The `checked` column says which surfaces the
lint reads from a repo tree (`tree`), which it judges only through `--check` (`check`), and which another tool or
review owns (`no`). A `view` cell makes a surface another one under a second name (`path.test` is `test`) or that
surface judged for some rules only (`case` is `path` reporting `name.case` alone). `repo-kind` is checked on a
directory, never in a tree scan: `.agents/config.yaml` names the kind and `repo-kinds.tsv` the entries it requires.

**A renderer with a `rule` is a grammar, not a description.** The lint parses a name back through the cell
(`--parse`) and renders a tuple with it (`--render`), so editing the cell changes what is accepted: no surface's
shape is written in `bin/lint-name.sh`. `<slot>` is a word group, `[...]` is optional, and anything else is
literal. `--self-test` fails when an example does not survive parse then render unchanged. A `bin/` script, a
skill and a test may be the bare family (`bin/worktree.sh`), the family's default action (D-13).

### 6.2 Symbols: one meaning each

| Symbol | Meaning | Never |
|---|---|---|
| `/` | containment: dir/leaf, system/register, tier/id, type/branch | inside a leaf |
| `.` | **in an id:** a level. **In a filename:** a leading dot hides it; the first interior dot starts the extension chain | as a word separator in a filename |
| `-` | joins words and terms | where the surface forbids it |
| `_` | only where `-` is illegal (sh, Python, env, JSON); leading `_` = private | in paths or ids |
| `:` | crosses into a register (`check:`, `lint:`, `plugin:skill`) | inside an id or a filename |
| `@` | version (`yard@1.2.0`) | in filenames (use `-v2`) |
| `#` | issue (`harbor#949`) | in filenames |

### 6.3 Edge cases

- **Acronyms** are words: `api-property`, `apiProperty`.
- **Numbers** never start a word, except in a date and the `NNNN-` ordinal of a decision record (MADR).
- **Tool-required dots:** launchd labels and plist names (`com.harbor.<id>.plist`) carry the id's dots, because
  launchd defines the label. This is a `tool-required` row in `exemptions.tsv`.
- **Dates** are a `YYYY-MM-DD-` prefix, on records and reports only.
- **Terms are singular.** Plural only for containers.
- **Extension chain:** every element is a registered extension, a `terms.tsv` row of class `extension`
  (`x.test.ts`, `x.d.ts`, `CLAUDE.md.tmpl`).
- **Extensionless** if and only if the file is a PATH command.

### 6.4 The names the system gives itself

- **The CLI is `harbor`, never `helm`.** `helm` is the Kubernetes package manager, and project-init's
  `prod_guard` denies `helm uninstall` in every repo it scaffolds, so a `helm` command would be blocked by our own
  guard. Lint T5 holds it; DEAD-ENDS.md records the rejected guard exception.
- **Domains of work take the world's word.** A thing that exists without Harbor (a tag manager, a data estate, a reporting
  API) keeps its own name, so someone who has never heard of Harbor can find it. The system's own parts take
  technical terms (§0, principle 4); the nautical words survive as `aliases.tsv` rows, `harbor` and `yard` as
  codenames and `helm`, `ship` and `pilot` as legacy aliases, each confined to the surfaces its row lists.
- **Frontmatter keys** are the harness's, used verbatim (`name`, `description`, `allowed-tools` and so on); no
  bespoke key is added.

## 7. Case and uppercase

**Case shows the role, the ecosystem decides the separator, each symbol has one job, and every exception names
the tool that forces it.**

- **Lowercase** for every file and directory (D-1), except names a tool we don't own looks up, `README.md`,
  `LICENSE` and `CHANGELOG.md`, and the language rules: React `Component.tsx`, Python `ClassName`, and
  `SCREAMING_SNAKE` env vars and constants.
- **The allow-list** is `standards/naming/exemptions.tsv`, rows of kind `tool-required`, each naming its tool.
- **Headings** are sentence case. **Spelling** is US English (D-16). **Language** is English only (D-42).

## 10. Enforcement

1. **Registry** at `standards/naming/`, TSV (D-9). Each file opens with a `#` WHY header and `standard_version`, a
   SemVer where adding is minor and removing an alias or changing the grammar is major (D-28), and its id column
   comes first. The six registers of D-61 are `terms.tsv` (with every closed set as a class), `kinds.tsv`,
   `surfaces.tsv`, `registers.tsv`, `controls.tsv`, and `aliases.tsv` with `exemptions.tsv`. `renames.tsv`,
   `repo-kinds.tsv`, `dialects.tsv` and `label-axes.tsv` stay beside them and are not copied into the six. `registers.tsv` names every
   file in the directory, those three included, and the lint reads exactly the files it names: a `*.tsv` with no
   row there is red (`name.registry-shape`).
2. **Lint:** `bin/lint-name.sh`, one POSIX `sh` + `awk` file, so yard can vendor it into any repo with no
   toolchain.
   - In harbor it runs as lint rule N4 of `bin/lint-conventions.sh`, so at pre-push and in CI. Write time is
     harbor#978; pre-commit does not run it.
   - `--check <surface> <name>` judges one name, `--changed` the names a branch adds or changes, `--added` only the
     paths it adds, and the default run the whole tree. `--format findings` prints the `kind TAB id TAB subject`
     record shape.
   - `--added` is the lint-conventions rule `standard.names-added` (warn): the backlog of legacy names stops growing
     while the rename waves wait. It judges paths, not the env tokens inside them and not the registry, so a branch
     is held to the names it brings in. Promoting it to block is a person's PR (§10.3).
   - It reads `standards/naming/` and, when present, the private overlay `harbor-private/terms.tsv`: client and system
     terms only (§13, D-85). Core carries no client term. A repo-local register for a workload's own domains is
     not built: it is part of the six registers.
3. **Mode, shadow → warn → block (D-29, D-64):**
   - Each control's mode is a cell of `controls.tsv`. **shadow** records a finding and prints nothing, **warn**
     prints it, **block** fails the run. `advisory` and `inform` are legacy spellings of warn, listed as the `alt`
     of that mode term in `terms.tsv` and never written.
   - `controls.tsv` holds every lint rule, check, admission rule, injection rule and CI gate (D-62), each with an
     owner family and a `red_proof`. An id the tree carries and the register lacks is red
     (`name.control-unregistered`); `registers.tsv` says where each type is found.
   - Every finding is red under its own rule id: `lint-name.sh` writes `name.<slug>` to `LINT_REDLOG`, and N4
     relays the finding without writing `N4`, so each rule has its own record.
   - Legacy names go into exemptions generated from the rules' first scan (`--gen exemptions`). That list only
     shrinks (`name.exemption-stale`, `name.exemption-grow`), and each row expires on the date of the rename wave
     that retires it (harbor#961), a week apart, so the list never expires on one day.
   - Promotion to block is a person's PR, after the rule has gone red and run 4 weeks with no finding accepted
     as false.
   - There are no inline ignores.
   - An expiring alias becomes a finding 14 days before its date (`name.alias-expired`).
4. **Self-reference:**
   - The registry and the lint are lint subjects like any other file.
   - `exemptions.tsv` refuses any row about the registry, the lint or its fixtures, and the lint never applies one.
   - `fixtures/naming/registry/fail/` goes red on a bad term, a duplicate id, a family/verb overlap, a control
     row that is not what the registry has, a control id no row holds and a grammar that does not parse.
5. **Proof it can fail:**
   - `fixtures/naming/<surface>/{fail,pass}/` with an `expect.tsv`, every `pass/` holding unusual-but-valid names.
   - Whether a rule went red is read from `LINT_REDLOG` during `--self-test`, never from the fixture text. The
     self-test fails unless every rule goes red on every surface its `controls.tsv` row declares.
6. **Generated from the registry** into untracked `build/` (D-40): glossary, naming guide, CLI tree (D-13), label
   set (D-30), Vale config and rule titles.
   - `--gen issue-taxonomy` renders `label-axes.tsv` (every label as `<axis>:<value>`, the legacy label it replaces,
     each axis's cardinality) into the connector's taxonomy format and a legacy-to-new map. Nothing is renamed on
     GitHub by it: label writes are an operator's, and the connector reads `CONTRACTS/issue-taxonomy.tsv` until then.
   - `sh bin/doc-vale.sh <file.md>` generates the Vale config and runs it. Without Vale it prints "verified NOTHING"
     and exits 3, never 0.
7. **Header and comment rules on added lines** (harbor#978): `bin/lint-comment.sh` judges only what a branch adds. A
   new script opens `# <name> (<repo>#N) — <purpose>` on line 1, or line 2 under a shebang (`lint.file-header`), and
   more than 3 added comment lines in a row are flagged outside a new file's header (`lint.comment-added`). Both
   are `warn` rows of `controls.tsv`. It is not yet called from `bin/lint-conventions.sh` (harbor#957 holds that file).

## 13. Workspace, private layer, packs and share (D-78 to D-85)

The target design is `DESIGN.md` of the core-packs deliverable; this section is the naming it fixed.

- **Workspace (D-78):** `$PORT_ROOT/` holds only `harbor`, `harbor-private`, `.worktrees`, `.scratch`, `history` and
  the repos named in `harbor-private/repos.tsv` (`id`, `path`, `kind`, `remote`; D-82).
- **Private layer (D-79):** `$PORT_ROOT/harbor-private`, data only: `harbor.toml`, `repos.tsv`, `terms.tsv`,
  `leaks.tsv`, `access/`, `checks.md`, `controls.tsv`, `jobs/`, `CLAUDE.personal.md`.
- **Pack (D-80):** `<workload repo>/harbor-pack/` with `pack.toml`, `skills/`, `bin/`, `inject.d/`, `checks.tsv`,
  `tests/`. No `hooks/`, no `guard-*`.
- **Config grammar (D-81):** `harbor.toml` and `pack.toml` are one flat TOML subset: one `key = value` per line,
  `#` comments, values a double-quoted string or a one-line array of them, no tables.
  - `pack.toml` keys: `name`, `version`, `harbor_version`, `description`.
  - `harbor.toml` keys: `packs` (repo ids), `components` (default `["core"]`; optional `yard`, `fleet`,
    `prod-guard`, `collector`), `channel` (`main` or `stable`), `deliverables_dir`, `worklog_repo`.
- **Share (D-83):** `layer` already means where a file lives, so the axis is named `share`. `kinds.tsv` lists the
  values a kind may take (a hook: `core`; a skill: `core,workload`); where an instance lives picks its value.
- **Commands (D-84):** `harbor pack install <id>`, `harbor pack remove <id>`, `harbor scope install`,
  `harbor deploy push` (core export, unbuilt; `scope` is private placement, publishing core is the `deploy` family).
- **Client terms and leak patterns (D-85):** `bin/lint-name.sh` reads
  `${HARBOR_SCOPE_PRIVATE:-$PORT_ROOT/harbor-private}/terms.tsv` when present. Patterns for the leak gate live in
  `leaks.tsv`, never in `terms.tsv`. `--self-test` ignores the overlay, so the suite is the same on every box.
