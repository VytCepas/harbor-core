Suites, CI and the merge gate

Every guard, every generator and every contract here has a suite, and the suites are selected by what changed rather than all run every time.

The suites, and what selects them

Change-class selection, and the direction it fails in

A docs-only pull request does not need the shell-guard corpus. A selector reads the changed paths against a declared mapping and runs only the suites that could be affected. Every uncertainty it meets resolves to running everything — a broken selector then costs CI time rather than coverage, which is the only acceptable direction for that failure.

The CI jobs

Jobs run even when their dependency failed

A continuous-integration system skips a job whose prerequisite failed — and a skipped required check does not block a merge, because nothing about it reads as failing. A red suite could therefore hide behind a check that looked satisfied precisely because it never ran. The fan-in jobs here run regardless and decide for themselves, which is the same defect class as a test that cannot fail.

Two things learned the expensive way

A cancelled check scores as a failure and never clears. Not as pending, not as neutral — as a permanent red that blocks every merge until the workflow that produced it is changed. This cost a morning here, and the merge backstop now uses the platform's own required-check oracle rather than reimplementing the scoring, because that oracle already encodes the rule.

Branch protection can lapse silently. On some plan and visibility combinations the protection endpoint simply returns an error, every rule stops applying, nothing turns red, and the next red merge succeeds. The backstop therefore checks that protection exists, not only that the checks are green. An override is written into the merge commit rather than only the terminal, because "was this merged red, and did someone decide that?" is answerable six weeks later only from the history.

A test that cannot fail is worse than no test

This is the rule the rest of the quality layer is organised around, and it is enforced by habit and by mutation testing rather than by a linter: break the thing a test guards, watch it go red, restore. That is the only evidence a test tests anything.

It is not hypothetical here. The injector's compaction rule had a passing assertion for its entire broken life, because the assertion checked that the engine produced output rather than that the output was accepted. A second class is quieter still: a group of silence-assertions once sat above the fixture whose absence they would pass without, making every one of them vacuous — exposed only because the paired must-still-fire half went red. Falsification proves discrimination, not correctness, so a new rule is asserted in both directions: the shape that must fire, and the near-miss that must not.
