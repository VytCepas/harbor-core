Vocabulary — the words for shape and evidence

A fixed lexicon for the two questions this repository keeps asking: what shape is this, and does the evidence support the claim. Imported from complexity science and information theory, each term kept only where it names something Harbor already does in a paragraph.

Five structural words — module, interface, depth, seam, adapter — are defined in DOCTRINE/modularity.md and are not restated here. A definition stated twice is a copy, and copies drift while reading perfectly. This chapter adds the words that had no home.

Structure and measurement

TermDefinitionWhat it names here
Real PatternDennett — a pattern is real iff describing the system through it compresses predictive information beyond the alternatives. The criterion the deletion test was missing. It is computable: compare the compressed size of the parts against the whole. A split that costs bits is bookkeeping, not structure.
Hidden varietyAshby — variety a regulator absorbs that never reaches its caller. Depth stated as a count rather than a judgement. Lines of implementation per externally callable symbol.
Requisite varietyAshby — a regulator must carry at least as much variety as the system it regulates.Why the argv layer cannot win by adding rules. The floor regulates a shell grammar with strictly more variety than its regex set, which is a proof about the approach rather than an item of backlog.
Coarse-grainingA quotient map identifying distinct microstates as one macrostate. A quotient, not a compression — it generates new relations.What segmentation does to a command line, and what compaction does to a session. The warning is the second clause: the quotient can invent adjacencies the original never had.
Multiple realizabilityOne macro pattern instantiated by many distinct micro configurations.Reading a skill file and invoking the skill tool are two realizations of one event. An instrument that counts only one scores the other as failure.
Sufficient statisticA function of the data preserving all information about a target and discarding the rest; the information bottleneck is compression with a purpose.What a skill description is for. A description advertising a method inventory is high in content and useless for routing.
Markov blanketThe minimal set making a system conditionally independent of everything else.A testable form of interface: it can be checked by conditional independence rather than argued.

Behaviour over time

TermDefinitionWhat it names here
MetastabilityStable on intermediate timescales, ultimately decaying. Most real macroscopic structure is metastable.A green suite and an unrevisited defect register. Neither is stable; both decay, and the decay reads flattering.
ResilienceCapacity to absorb perturbation without changing basin — distinct from robustness, which resists all change.The false-positive rule in one word. A guard optimised for robustness blocks ordinary work and gets switched off, and a switched-off guard protects nothing.
Delay / lagTime between cause and effect. Delays produce oscillation and overshoot.Confident fixes whose defects surface a pass later. The incident is recorded; this names the mechanism.
Path dependenceState depends on the trajectory taken, not only on present conditions.An installed tree is not a checkout. A file no installer ships keeps whatever version it was born with.
Leverage pointsMeadows — places where a small intervention produces a large change. Higher leverage is paradigms; lower is parameters.Orders the layers a fix can land in: constitution, doctrine, lint rule, guard pattern, note. The ordering was assumed and is now named.

Evidence

TermDefinitionWhat it names here
Observer / reflexivityThe observer is part of the system observed. Measurement, partition and modelling are not extra-systemic.The failure mode of every instrument here: a skill-firing probe leaking its own fixture into the prompt, a ledger assertion writing to the ledger it reads, a routing counter blind to the route this repository trains. Four separate incidents that had no shared name.
Semantic informationKolchinsky & Wolpert — the subset of syntactic information whose erasure, by graded scrambling, reduces viability.Not a term but a method: scramble a section of the instruction surface and measure whether the work degrades. It is the only proposed route to finding which pinned bytes are load-bearing.
Endogenous / exogenousWhether a measurement reads the system's own output or an independent signal.Defined in DOCTRINE/verification-expanded.md. Every check that reads a pipeline's own output proves consistency, never correctness.

Shape: modular and microservice are two axes, not one

The confusion this section exists to end is that modular and microservice sound like the same direction. They are perpendicular, and every combination of them occurs.

One moduleMany modules
DeepDeep monolith. Large implementation, small interface. Nothing wrong with it.Services. Each module deep, few seams crossed per task. The target.
ShallowBall of mud. Everything public, nothing hidden. Interface nearly as complex as the implementation. Distributed monolith. Many modules, each thin, all reaching into each other. The worst cell, and the one reached by splitting for its own sake.

Splitting a file moves one axis only. Cut a deep module into seven pieces and its hidden variety per symbol does not change — the same implementation sits behind the same symbols. What changes is how many seams a task crosses. So fragmentation is never evidence of modularity, and a file count is never evidence of either.

The falsifier for a seam

Cutting that deep module at arbitrary line boundaries makes the parts cost substantially more compressed bits than the whole, while cutting it along real function boundaries costs almost nothing. That gap is Dennett's criterion made operational: a boundary that costs bits is not a real pattern, and it can be detected without reading the code.

A real boundary is not a boundary worth crossing

The compression test answers whether structure exists at a file's own boundaries. It does not answer whether anything should be split, and treating one question as the other is how a measurement talks a codebase into fragmenting. Run across every file here over three hundred lines, the reality test alone marks 36 of 52 — every test suite included, because a suite genuinely is a flat list of independent blocks whose boundaries nothing crosses. The second question is the two-adapter rule made countable: symbols with at least two callers outside the file. Two files clear that bar, and under both conditions not one file earns a split.

The shared guard library is the instructive case: thirteen of its symbols are called from two or more other files, and its own function boundaries score below the reality threshold. It is correctly one deep library rather than a set of them.

Density, not edge count

Coupling has to be measured as the fraction of possible module pairs that actually call each other. A raw edge count cannot distinguish one shared deep library with many independent callers — a hub, which is the good shape — from every module reaching every other, which is the distributed monolith. Both produce large counts. Only density separates them, and the same trap catches destination entropy, which scores a pipeline and a mesh alike.

Harbor's own bin/ was measured against these definitions on 2026-08-30 and sits in the deep-and-fragmented cell with a hub topology: depth roughly a hundred lines per public symbol, near-zero call density, and the large majority of cross-file calls landing on the shared guard library. Both questions are re-derivable — bin/module-shape.sh, whose suite builds ten synthetic codebases and proves each lands in the quadrant it was constructed for. The suite is the load-bearing half: the instrument mis-measured four times before it settled, every one caught by a control rather than by review, and every one wrong in the direction that made a split look earned.
