watches: a `gh pr merge` a session runs as a tool call from any folder (limits: docs/explanation/admission-baseline.md, govern-hook --box). The target repo is the `-R` slug's checkout under the port root, or the call's working folder, and it is judged only if it is a registered project (the private layer's `inject.d/box/projects.tsv`) carrying `bin/gate-merge-check.sh` (today, harbor)
schedule: **not scheduled.** It runs before every Bash call (PreToolUse), box-wide, through `govern-hook.sh --box` (harbor#516). A session launched in the repo is covered by the repo's own merge pack instead
notifies: a deny on the tool call, stamped `[check:gate.merge-backstop]`. A pass or an unverifiable merge is a note, never a block
red: `gate-merge-check.sh` refused this PR: a check is not green, or branch protection lapsed. Merge with `sh bin/gate-merge-check.sh --merge <N>`, or add `--force` to record an override in the merge commit. A merge you run with `!` in your own terminal is not a tool call and never reaches it. Silence on a red PR means the hook is unwired or broken: `sh bin/admission-verify.sh --live` probes it. Disable: `sh bin/deploy.sh --apply --only floor --uninstall --live` (`harbor uninstall`) removes it with the rest of the floor. Deleting only its hook entry from `settings.json` is wiring drift, which B6 reports at the next SessionStart
