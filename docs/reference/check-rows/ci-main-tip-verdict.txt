watches: **whether main's tip, and each of the last 30 first-parent commits, has a green CI verdict, in every fleet repo** (harbor#586, fleet harbor#1088), by `bin/ci-main-tip-verdict.sh`. The fleet is read where `ci-runners.sh` reads it: harbor, the snapshot's repos that carry `.github/workflows` and a github origin, and the `repo` lines of `.harbor-ci-runners`. A commit is read from ITS push and scheduled runs, never a `gh run list` page: green (some run succeeded), pending, failed (a failed run, or a workflow's LATEST scheduled run on that commit failing, even beside a green push run), cancelled-only, no-run (asked again by sha before it is believed). A repo whose main workflows are all disabled is `disabled`, one with no push/schedule run on main is `no-ci`: neither is red
schedule: every 300s, inside `status.fleet-snapshot`'s run rather than on a schedule of its own. GitHub calls per tick: one `commits` read per repo, plus (only for a repo whose tip changed, is not green, or was last read over an hour ago) one `runs` list, up to 10 by-sha reads and, for a red tip, one `workflows` read; a disabled or no-ci repo costs none for an hour. Falsifier: `sh tests/ci/main-tip-verdict/main-tip-verdict.test.sh` and the MAIN RED cases of `sh tests/status/statusline/row2.test.sh`
notifies: **Findings land in two places, and the report is the delta, never the census.** (1) the statusline alarm `MAIN RED <repo> <age>` (two repos listed, more as `3 repos, oldest 4d`), drawn from `~/.claude/cache/main-tip-verdict.json`, age counted at print time from the tip's commit time; `main?` when the cache is over 900s old or a repo's read failed and none read is red. (2) one `[check:ci.main-tip-verdict]` line in `~/.claude/cache/checks.log` per CHANGE per repo (a new non-green commit, the tip's verdict changed, a repo gone disabled) and none for a standing state. No desktop notification. Detail by hand: `sh bin/ci-main-tip-verdict.sh --print` (red or newly non-green repos in full, the rest one `green:` line; exits 1 on a red tip, 3 when a repo was unread and none was red, 2 on a bad option). (3) its receipt `~/.claude/cache/checks/main-tip-verdict.json` on every write run, red over the non-green commits' short shas (harbor's bare, other repos `name:sha`), which `lint-findings.sh reconcile` files as finding `check/ci.main-tip-verdict` (harbor#896)
red: a merged commit has no green run in a repo that gates on it. `MAIN RED estate 3h` is a TIP that is failed, cancelled-only, no-run, or pending over 2h. A red tip under a later green one is gone from the alarm but stays in the cache as standing. A failed read keeps that repo's last entry, flagged unread, never green. **It reports and re-runs nothing**: `gh run rerun <id> -R <repo>` is a person's call, because a re-run from an unreviewed signal hides the thing found.
