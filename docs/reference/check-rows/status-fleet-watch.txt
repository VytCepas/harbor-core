watches: **the fleet's health over time, not just now** (harbor#1437): the fleet controller's `watch` pass, by `bin/status-fleet-watch.sh`: the CI, cloud and supervised-process probes refresh across every repo `fleet.yaml` names, the checks history is appended (the trend column), and the threshold alerts (CI red, drift, hooks, cloud) come back as JSON. Only the lint gate runs locally (`--task lint --changed-only`); the tests of every repo each hour would queue behind the CI governor. `watch` has no webhook (it emits and exits), so this job is the only notifier a scheduled pass has
schedule: once an hour, inside `status.fleet-snapshot`'s run rather than on a schedule of its own: that job's 300s tick calls it with `--if-due` and a stamp younger than 55 minutes ends the tick; bounded to 900s; the `--interval 3600` it passes lets the controller tell a stale watch from a fresh one. By hand: `sh bin/status-fleet-watch.sh`; falsifier: `sh tests/status/fleet-watch/watch.test.sh`
notifies: the existing findings channel: one receipt, `~/.claude/cache/checks/status.fleet-watch.json`, which the daily `lint.findings` reconcile files as the issue `check/status.fleet-watch` on harbor (subjects `<project> <category>`) and closes as fixed when a fresh receipt is green. The run's report is the delta (new, fixed, standing), never the census, and one `[check:status.fleet-watch]` line in `checks.log` for a run that changed something
red: an alert is new since the last run (exit 1): a repo's CI is red, its deployment or process is down, its lint fails, its scaffold drifted or its git hooks are missing or stale. Detail: `sh bin/status-fleet-watch.sh`, or `projects-orchestrator watch --fleet <fleet.yaml>` for the full pass. Exit 3 (no controller or fleet file, `watch` judged nothing, or the 900s bound killed it) writes a stood-down receipt, never a green one.
