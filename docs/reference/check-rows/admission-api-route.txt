watches: the settings files Claude Code loads (`$CLAUDE_CONFIG_DIR/settings.json` and `settings.local.json`, and the project's `.claude/` pair, from `CLAUDE_PROJECT_DIR`) for the keys that decide WHERE its requests go or HOW they authenticate: `ANTHROPIC_BASE_URL` and its siblings, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_API_KEY`, the Bedrock and Vertex switches, the proxy variables and `apiKeyHelper`. Each file is held against the copy the guard last accepted: a route key added or repointed since is put back by restoring that copy, a file that arrived under watch loses only its route keys (jq), and the rerouted copy is kept beside it. A file read for the first time is accepted as it is, and any route key in it is reported once, never deleted
schedule: after every Bash, Write, Edit and MultiEdit call (PostToolUse), and at SessionStart
notifies: a block reason on the tool call, SessionStart context, and `checks.log`
red: something a session ran pointed Claude Code at another endpoint or credential. On 2026-09-17 claude-code-router 3.1.0 did, and every session on the box failed with `Connection refused` until the file was restored by hand. A red that says `NOT REPAIRED` needs the operator. A gateway that is wanted is allowed by listing its keys in `$CLAUDE_CONFIG_DIR/.helm-apiroute-allow`. Disable: remove the two `admission-api-route.sh` hook entries from `settings.json`; `sh bin/deploy.sh --apply --only floor --uninstall --live` (`harbor uninstall`, harbor#808) removes them with the rest of the floor
