watches: **what each session is waiting on** (harbor#1043, #1044): the Stop hook `hooks/session-state/session-state.sh` classifies the turn that just ended as waiting-agents, waiting-operator (patterns in `contracts/session-waiting.tsv`, one test each), blocked (guard-stop SG-2, the same awk), done or idle, writes `~/.local/state/harbor/sessions/<session_id>.json` and appends `session.state` only on a change
schedule: **not scheduled.** It runs at every Stop, wired by `runtime-install`; under 300 ms on a 348 MB transcript (3 MB window); falsifier: `sh tests/session/state/stop.test.sh`
notifies: the record, the statusline token (`✓ done`, `? you`, `⧗ N agents`, `✗ red`), the `session.state` event and the post-compaction carry. Prints nothing else, except one opt-in `additionalContext` for `event.session-save-now`; on a finished turn at ≥35% of the window one more continuation asks the agent whether to compact, and when the agent ends a turn with the line `[compact-ok]` it starts `bin/session-autocompact.sh`, which types `/compact` into the session's Terminal tab (harbor#187; off: `touch ~/.local/state/harbor/compact-auto.off`). When a PR the session opened has merged (a `pr.merged` event for one of its `pr.opened`), one continuation asks whether everything is finished; a turn ending with the line `[cleanup-ok]` starts `bin/session-cleanup.sh`, which runs `housekeeping-clean.sh --apply --live` (RECLAIM rows only) and re-records the sweep (off: `touch ~/.local/state/harbor/cleanup-auto.off`). Neither run prints to the operator; each logs under `~/.local/state/harbor/backups/`. Exit 0 on every path
red: a stale or wrong token on the statusline, or reactions firing on a wrong state; the record is data, never a verdict on the work. Disable: `touch ~/.local/state/harbor/session-state.off` (stops it at once) or `touch ~/.claude/session-state.off` (`runtime-install` then stops wiring it)
