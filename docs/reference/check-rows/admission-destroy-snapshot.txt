watches: **a git command a session runs that discards uncommitted work** (harbor#1290), by `bin/admission-destroy.sh`: checkout or restore with a pathspec, `reset --hard`/`--merge`, `checkout -f`, `switch -f`/`--discard-changes`/`-m`, `clean -f`. Before it runs, the worktree it acts on (the call's `.cwd` through `cd`/`pushd` and `-C`) is saved to `refs/snapshots/<epoch>-<pid>`: tracked changes and untracked non-ignored files, the real index untouched. A clean tree and a branch switch take none; refs over 7 days old go when the next is written. Also a `git push` that would publish `refs/snapshots` (`--mirror`, a `refs/*` refspec, a mirroring remote) in a repo holding any
schedule: **not scheduled.** It runs before every Bash call (PreToolUse), inside the guard-destroy hook already wired; no hook of its own
notifies: one stderr line per call, stamped `[check:admission.destroy-snapshot]`, only when a snapshot could not be taken (an unwritable repository, a folder it cannot resolve). Success is silent: the evidence is the ref. A push that would publish snapshots is a deny on the tool call
red: the discard ran with no copy of what it threw away. The command itself always runs exactly as before; nothing here asks or refuses a discard. Recover: `git for-each-ref --sort=-committerdate --format='%(refname:short) %(committerdate:relative)' refs/snapshots/`, then `git restore --source=snapshots/<id> -- <path>` (docs/explanation/admission-baseline.md, harbor#1290). Not seen: git run inside a script or subprocess, and the operator's own terminal. Disable for one repo: `touch "$(git rev-parse --git-common-dir)/harbor-snapshot-off"`; drop one: `git update-ref -d refs/snapshots/<id>`; remove entirely: `sh bin/deploy.sh --apply --only floor --uninstall --live` (`harbor uninstall`) with the rest of the floor
