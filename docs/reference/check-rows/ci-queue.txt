watches: **how long until this box's CI runners are free** (harbor#657, operator request 2026-09-23): for every repo a folder under `~/runners` is registered to, the jobs still to run and the epoch the last should finish, by `bin/ci-queue.sh`. Each job's typical length is the median of its last three successful runs; queued jobs are scheduled on the free runners; `needs:` is not modelled, so it runs short. A queued run over a day old is a GHOST and is counted, never scheduled. **And a stall (harbor#152):** a self-hosted job queued over 600s while a runner of that repo is online and IDLE, on two refreshes in a row, is a wedged runner, not a queue
schedule: every 300s, inside `status.fleet-snapshot`'s run rather than on a schedule of its own; falsifier: `sh tests/ci/queue/queue.test.sh` and the ⏳ cases of `sh tests/status/statusline/row2.test.sh`
notifies: the statusline: `⏳N ·~Mm` in grey, the minutes subtracted at print time from the cached epoch. No desktop and no `checks.log`: it is information, not an alarm. Detail by hand: `sh bin/ci-queue.sh --print`
red: **`CI STALL`** in the alarm zone is the one red: a runner is wedged and nothing will merge until it takes work. `sh bin/ci-queue.sh --print` names the idle runner and its restart (`cd ~/runners/<name> && ./svc.sh stop && ./svc.sh start`), which is safe because an idle runner is running nothing; it is never run for you. A stall from a cache over 900s old is not claimed. Otherwise idle renders nothing. `·due` is a job past its usual length; `?` is a repo GitHub did not answer for, or a cache over 900s old, and then the time is dropped.
