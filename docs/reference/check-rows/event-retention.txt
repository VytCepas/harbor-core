watches: the event bus's day files, `${HARBOR_EVENT_DIR:-~/.local/state/harbor/events}/YYYY-MM-DD.jsonl` (harbor#1043): a file dated more than 14 days before today's UTC date is deleted, so every event is kept at least 14 days and the bus never grows without bound. The date is read from the file name, never its mtime
schedule: **not scheduled — no launchd job.** It rides `bin/event-bus.sh emit`: the first emit of each UTC day sweeps once (the day is stamped in `prune.day` beside the files); by hand, `harbor event prune`; falsifier: `sh tests/event/bus/prune.test.sh` (a 15-day-old file beside a 14-day-old one; keeping 15 days reddens it)
notifies: stderr of the process that emitted, and only on a failure: `FAIL: [check:event.retention] <file> is older than 14 days and could not be deleted`, then `fix: rm -f '<file>'`; the emit still exits 0. A typed `harbor event prune` prints `ok: [check:event.retention] removed N day file(s) …` and exits 1 on any failure. No `checks.log` line, no receipt
red: an expired day file survived: the bus dir is not writable by whoever emits, so the bus grows by a file a day until the fix line runs. No event was lost and no producer failed. Disable: `touch ~/.local/state/harbor/events/prune.off` (or `$HARBOR_EVENT_DIR/prune.off`); a typed `harbor event prune` still runs. Retire it with the bus: this row, `prune` in `bin/event-bus.sh` and `tests/event/bus/prune.test.sh`
