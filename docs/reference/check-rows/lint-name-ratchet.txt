watches: **whether the naming findings moved without the baseline** (harbor#967), by `bin/lint-name-ratchet.sh`: it runs `bin/lint-name.sh --format findings` and compares each `<rule> TAB <subject>` with `contracts/lint-name-baseline.txt`. A finding the baseline lacks (NEW) is red; a baselined one that no longer occurs (STALE) is red until its line is deleted, so the baseline only shrinks. `standard.names-conform` still prints every finding as advisory
schedule: not scheduled: runs in every `lint-conventions` run (PR CI); by hand `sh bin/lint-name-ratchet.sh` (`--current` prints the keys). Falsifier: `sh tests/lint/name/ratchet.test.sh` (a planted bad name red and removed green; a deleted baseline line for a live finding red; a stale line red; a missing baseline red; an unreadable judge is not a pass)
notifies: the `lint-conventions` summary (`VIOLATION [lint.name-ratchet]` with NEW or STALE and the key); locally the `lint-name-ratchet` log lines on stderr
red: a branch added a bad name (NEW: rename it, or register the word in `standards/naming/words.tsv` if it is genuine vocabulary, never add the line to the baseline) or fixed one (STALE: delete its line). Disable: delete `rule_lint_name_ratchet` from `bin/lint-conventions.sh`, this row, the `lint.name-ratchet` and `check.lint.name-ratchet` rows in `standards/naming/controls.tsv`, `bin/lint-name-ratchet.sh`, `tests/lint/name/ratchet.test.sh`, `contracts/lint-name-baseline.txt` and their lines in `contracts/suites.txt` and `contracts/suite-paths.txt`
