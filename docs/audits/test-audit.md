## Summary

- **385 suites, 2 CI jobs.** harbor-core's governance workflow splits the selected suites over `suites 1/2` and `suites 2/2` (`bin/test-suite-run.sh --shard`). The `suites` job then tallies four groups from `contracts/suites-tally.txt` (`lint`, `floor`, `marker`, `normalize`), and the `conventions linter suite` and `security-floor suite` jobs report two of them. **No suite runs twice.** Each one is in exactly one shard (`--plan --shard 1/2` and `2/2` give 215 and 170).
- **CI seconds come from harbor-core's hosted runners.** Each figure is the median of the `ok: Ns <suite>` lines across up to four governance runs on 2026-10-30 (41133576029, 41046731084, 41034522891, 40978914266). "Recorded s" is `tests/suite-durations.tsv`, last written at `eb537273`. The two columns disagree where a suite skips on the hosted runner: `panels.test.sh` takes 0 s in CI and 37 s locally (#1409).
- **History.** 109 commits matched a bypass pattern or deleted assertions that the same commit did not re-add. Reading each one gave **102 clean, 3 weakened, 4 bypassed**. Nearly every assertion-removing commit removed its subject in the same change: cu, meta and stape left core, the decision block was reverted, worklog-pull was retired. **The premise "sessions hide bugs in tests" found 3 live weakenings in 385 suites, all minor.** The larger class is the 4 suites that **skip green in CI** because the hosted runner has no bun or vale.
- **Mutation pass.** Each suite's guarded file was emptied: a shell script returns 0 before its first statement, awk or jq becomes an empty program, Python or JS exits 0 first, and a data file loses its last row or all its bytes. That covers 207 distinct files. **379 suites went red on the first mutation.** 6 stayed green. 5 of those had been pointed at the wrong file, and each went red on a mutation of the file it really guards. **`tests/skill/gates/gates.test.sh` stayed green under both of its checkers emptied**: it asserted only `--self-test` exiting 0. It is repaired here.
- **This mutation is coarse.** "The tool does nothing and exits 0" proves the suite *runs and asserts on* the file. It does not prove the suite catches a subtle defect. The 2026-10-02 pilot used targeted mutations and found 4 of 15 suites blind (#905). A green under this mutation is a strong finding. A red here is weaker evidence than a red under a targeted one.

## Method, so it can be re-run

The scripts were run from a scratch directory outside the repo. This section is their contract.

- **Inventory.** The suite list is `contracts/suites.txt`. A suite's shard comes from `sh bin/test-suite-run.sh --plan --shard K/2` and its tally group from `contracts/suites-tally.txt`. CI seconds are the `ok: Ns <suite>` lines in the `suites K/2` job logs (`gh api --allow-escape-sequences repos/VytCepas/harbor-core/actions/jobs/<id>/logs`). Suites renamed by W8 (`eb537273`) are matched to their old names through `git log -M --diff-filter=R`. "What it guards" is the suite's own header line 2.
- **Forensics.** For each suite, `git log --no-merges --follow -M -p` emits a lead for every commit that adds a bypass shape to the file, or deletes assertion lines the same commit re-adds nowhere. Bypass shapes are a skip, `|| true` or `|| :` on an assertion, a bare `exit 0`, a commented-out assertion, or `t_eq` turned into `t_has` on the same label. Assertion lines are the `t_*` calls and the older `ok`/`bad`/`no`/`gone` helpers. A second pass separates moved lines from new ones: a bypass line whose text the commit removed elsewhere was moved, and a removed assertion whose quoted label the commit added elsewhere was reworded. Every remaining lead was read as a diff, together with the commit's non-test half. **What this cannot see:** history from before a suite was split out of a bigger file (`--follow` follows one path; the 2026-09-24 audit covered the parents), and a loosened expected value that keeps the same label.
- **Mutation.** The guarded file is the one the suite names most specifically. Each reference to a code file in the suite and the helpers it sources is weighted by how few other suites name it, files declared in `contracts/suite-paths.txt` count triple, and a file whose name carries the suite's own name gets a bonus. 43 picks were then corrected by hand from the suite's header. Each suite ran alone in a scratch worktree at `d29bfcaa`, one at a time, inside a `bin/ci-governor.sh` slot. A run stopped at the first `  FAIL: ` line (red) or at its own exit. The file was restored with `git checkout`, and the run refused to continue unless `git status --porcelain` came back empty. All 385 restores came back clean. The pass took 2309 s of suite time.
- **Was each red caused by the mutation?** A full unmutated run of all 385 suites was not affordable tonight: the box ran at load 77 to 85 on 10 cores, and the previous full run on this branch took 5.2 h of wall time. Three things stand in for it. (1) Every red's first FAIL line is in the last column, and nearly all are the shape an emptied tool produces: `got ''`, `got 'allow'`, `missing:` or `exit 0`. (2) Two unmutated runs were started and stopped under load, and only their finished suites count: 4 of a 36-suite sample on `d29bfcaa` passed (context-rules, access-confinement, atlas zones, redteam-corpus), and 2 of the 27 suites `--select` picks for this branch passed (fresh-verify, deploy). Three more passed unmutated as part of their repairs (gates, deploy, first-run). (3) The other sessions' full runs of the same branch the night before: `default-way` at 05:51 passed 383 of 385 (b6 and wait-for output-contract failed under load), and the 2026-10-30 harbor-core CI runs passed all of them.
- **Limits.** Emptying a file is the coarsest useful mutation. A suite red here can still miss an off-by-one; that question is the targeted-mutation method of `skills/test-strength` (#905), applied one suite at a time.
