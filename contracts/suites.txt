# SUITE MANIFEST (harbor#61) — the list of test suites CI must run.
#
# WHY THIS FILE EXISTS. Rule C3's guarantee is "no test suite sits silently
# outside CI". It used to enforce that by requiring every bin/*-test.sh to be
# named in .github/workflows/governance.yml — which an agent cannot edit,
# because permissions.deny covers .github/workflows/** deliberately, and that
# deny exists to stop an agent rewriting the gate that judges it.
#
# So adding a suite required a human round-trip, forever, for a mechanical edit.
# The two tempting shortcuts are both wrong and both already argued down in #61:
# a C3 exemption lets a suite sit outside CI silently, which is the whole thing
# C3 prevents; and a Bash carve-out for .github/** reopens the hole the deny
# closes.
#
# This file is the third answer. It is TRACKED and AGENT-EDITABLE, it is not a
# workflow file, and CI iterates it. Adding a suite is now one line here.
#
# FORMAT: one suite filename per line, relative to bin/. Blank lines and lines
# beginning with `#` are ignored. C3 checks BOTH directions — every
# bin/*-test.sh appears here, and every line here names a file that exists — so
# neither a new suite nor a deleted one can drift out of the list unnoticed.
#
# A MANIFEST NOBODY READS IS DECORATION. C3 also requires that this file is
# actually consumed: either governance.yml reads it, or (until that patch is
# applied by the operator) every suite is still named in governance.yml
# directly. The rule is never satisfied by the list alone.
