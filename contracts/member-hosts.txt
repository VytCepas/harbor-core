# member-hosts.txt (harbor#1278) — the hosts a member laptop's sandboxed commands may reach, beyond core's contracts/confinement-hosts.txt.
# One host per line, in Claude Code's `sandbox.network.allowedDomains` shape: at most one leading `*.`, never a bare `*`.
# Each row sits under a comment naming its purpose. bin/member-managed.sh composes core's rows, these, then signed policy `hosts`.
#
# WHY A LIST AND NOT AN OPEN NETWORK. The operator chose an allowlist widened on demand (2026-11-07, reversing open network):
# `deniedDomains` matches names only, so with the network open an agent reaches any host by its address or through a tunnel.
# The list starts wide enough for normal work. A host a person needs is added by the admin in signed policy `hosts`, and reaches
# a laptop when IT runs the install again (docs/how-to/member-install.md, "The network").
#
# Already in core, so not repeated: github.com, api.github.com, GitHub's Actions log and results hosts, objects.githubusercontent.com,
# api.anthropic.com (a nested `claude -p`), pypi.org and files.pythonhosted.org (pip and uv).
# Not Anthropic's other hosts: the sandbox covers shell commands only, and Claude Code's own traffic doesn't pass through it.
# Left out on purpose, because anyone can publish arbitrary content there and no package tool needs them: raw.githubusercontent.com,
# gist.githubusercontent.com, a `*.githubusercontent.com` wildcard, Launchpad PPAs, and any cloud-storage wildcard.
# Never a support relay: bin/member-managed.sh refuses a row that admits one, because the agent must not reach a session.

# GitHub release downloads: `gh release download`, `uv python install` and installers fetching a release asset are redirected here
# from github.com (checked 2026-11-08 against an upterm release)
release-assets.githubusercontent.com
# GitHub source archives: an npm `github:` dependency and a pip URL ending in /archive/... redirect here from github.com
codeload.github.com

# JavaScript and TypeScript: npm, npx, pnpm and bun read packages and their tarballs from the npm registry
registry.npmjs.org
# Yarn classic resolves through its own mirror of the npm registry
registry.yarnpkg.com
# Node.js itself, and the headers node-gyp downloads to build a native module
nodejs.org

# Ubuntu's package mirrors, which a WSL or Linux member's distro uses. A missing prerequisite is installed by the root helper outside
# the sandbox (contracts/member-prereqs.txt); these rows serve `apt-get download`, `apt-get source` and a container build in the sandbox
archive.ubuntu.com
# the country mirrors, such as lt.archive.ubuntu.com, that an install's sources.list may name instead
*.archive.ubuntu.com
security.ubuntu.com
# arm64 distros, such as WSL on a Windows on ARM laptop, read ports rather than archive
ports.ubuntu.com
